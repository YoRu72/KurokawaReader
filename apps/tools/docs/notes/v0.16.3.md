### Fixes
- **Player — the black picture with sound, found at last**: the element that stands in for mpv's picture on the page carried the page's black video background, so it covered the picture mpv drew beneath it — on every file mpv plays (MKV, HEVC, 10-bit…), the first as much as the rest. Measured on an Erai-raws-like HEVC 10-bit MKV with ASS subtitles: the picture's area left clear for mpv went from 0% to 100%. Two tests now guard it (nothing on the page may paint over mpv's picture; the picture's share left clear is measured while playing and under the controls).
- **Anime — «Failure in SSL library … HANDSHAKE_FAILURE»**: on some networks the phone's own HTTP client is refused at the TLS handshake by AniList. Such a request is now made again through the web view's own network stack — the way Hayase reaches AniList — and that route is kept for the site a day. The same holds for any site that allows it (Cinemeta among them). With DNS over HTTPS on, a site refused at the handshake through the resolver's rewritten hello is asked the plain way (the network's DNS, the hello as it is) and kept so for a day — the likely reason the Anime tab stopped working after DNS over HTTPS was turned on. A busy AniList (429) is waited for as long as it asks, a failing one (5xx) retried once.
- **A download's page — the speed figures laid over the title**: the player's statistics box and the download page's Now · Average · Peak · Time left shared a name, and the player's position won; they are apart again.
