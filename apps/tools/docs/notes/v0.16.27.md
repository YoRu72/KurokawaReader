### Fixes (screen translator)
- **Translated boxes stay on their text while you scroll slowly.** A slow scroll was not noticed at all in capture mode, so the boxes drifted away from the words.
- **No more flicker on every read.** Every box used to be removed and drawn again each time the screen was read. Now only new or changed text is redrawn, and small corrections glide into place.
- **The same text is not translated twice.** A stray space or one misread letter used to send the line for translation again. A changed number (3 likes → 4 likes) is still translated again.
- **Boxes no longer vanish when the page moves too fast to follow.** They are hidden for a moment and put back on their text.
- **Toolbars and fixed bars stay still.** Only the boxes inside the part that scrolls move with it. Sideways scrolling is followed too.
- **The keyboard is left alone.** Its keys were being read and translated, and boxes were drawn over it.
- A scroll that happened while the screen was being read is no longer missed.
- A line cut off at the edge of the screen no longer replaces the whole line's translation.
- Changing settings no longer throws away the translations already made.
- **Easier on the battery**: a screen that isn't changing is read less and less often (down to once every 3.2 s), and at once again when it moves.

### Translate ahead (new)
- **What's below is translated before you scroll to it**, so it is already there when it appears. On by default, in the screen translator's Auto card ("Translate ahead").
- It works where the app shares the text below the screen (accessibility mode): web pages and ordinary scrolling screens work well, while many lists only share the next row or two.
- In capture mode nothing below the screen can be seen. There, anything seen before appears at once, and the strip scrolling into view is read first.
- It uses some data and translation quota. Paid keys (DeepL, AI) get a small allowance, and it pauses for two minutes after any failed request.
