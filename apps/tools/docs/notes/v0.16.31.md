### Fixes (Files)
- **Moving files can no longer delete what was not moved.** Before: choosing "Skip" when a name was taken deleted the original anyway; cutting a file and pasting it into the same folder deleted it; a move that was cancelled or failed between two storages could lose the original. Now an original is removed only after its own copy is complete and checked. Anything skipped, failed or cancelled stays where it was, and you are told how many were left.
- **Replacing a file is safe.** The new file is written beside the old one and swapped in at the end, so a copy that fails no longer destroys the file it was replacing.
- **A folder can no longer be copied or moved into itself.** It used to copy itself deeper and deeper until storage filled.
- **Batch rename keeps the file type.** A name with dots in it, such as `Show.S01E01.720p.mkv`, lost its `.mkv`. If two files would end up with the same name, the clash is shown and nothing is renamed.
- Deleting a folder that holds a link no longer deletes what the link points to.
- Renaming a file to the same name in different letter case no longer overwrites another file.
- **Two panes**: a slow folder's list no longer appears over a newer one, and each pane handles only the jobs it started.
- Closing the "name taken" question now cancels the job. It used to leave the job waiting forever.
- **Copy stays on the clipboard**, so the same files can be pasted in several places. "Clear the clipboard" is in the + menu. Cut files are taken off the clipboard only once they have moved.
- When items cannot go to the bin, you are asked whether to delete them for good. They used to be left in place with only an error.

Changes you may notice: copying and pasting into the same folder makes "name (1)"; cutting and pasting there does nothing; moving into a folder that already exists asks about each file with a taken name.
